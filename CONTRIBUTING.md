# Contributing

Read `docs/engineering-discipline.md` before changing Matter.

- One branch and pull request per logical change.
- State the user-visible claim and smallest affected boundary.
- Preserve protocol and product invariants unless the change deliberately updates
  an ADR.
- Run the narrowest relevant validation and report exact commands.
- Keep unrelated refactors, dependency upgrades, and formatting churn out.
- Record deferred work and known risks honestly.

A pull request should include: what changed, why, validation, risks, and deferred
work.
